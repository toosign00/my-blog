# 브라우저·서버 연동 테스트

Playwright와 Next.js의 실험적 testProxy를 사용합니다. 테스트는 `e2e/*.spec.ts`에 둡니다.
Jest는 순수 로직과 Client Component를, Playwright는 실제 개발 서버의 페이지·MDX·Route Handler를 검증합니다.

## 실행

```bash
pnpm exec playwright install chromium webkit
pnpm test:integration
pnpm test:e2e
```

빌드는 실행하지 않습니다. 전용 포트 3100과 `.next-e2e` 출력 경로를 사용하며 기존 서버는 재사용하지 않습니다.
Playwright가 서버를 시작·종료하고, 실패 시 `test-results`에 trace와 screenshot을 남깁니다.
CI에서는 `.github/workflows/e2e.yml`이 매주 월요일 09:00(KST)과 수동 실행 시 돌며, 실패하면 `test-results`를 아티팩트로 7일간 보관합니다.
PR 실행 조건은 추가하지 않습니다. 주간·수동 실행에서는 실제 HTTP 회귀 검사도 함께 실행합니다.

기본 명령은 Chromium 전체와 WebKit 핵심 흐름을 실행합니다. WebKit 범위는 프로젝트 검색·조건 복원,
모바일·키보드 사용, 테마 유지, Clipboard API가 없는 환경의 공유 대체 동작과 오류·복구 4개,
고정 이미지 표시 및 미등록 이미지 도메인 차단입니다.
브라우저별 실행은 `pnpm test:e2e --project=chromium` 또는 `pnpm test:e2e --project=webkit`을 사용합니다.

## 격리와 범위

- 서버 자격증명은 설정 파일의 가짜 값으로 덮어씁니다. 운영 DB 쓰기와 실제 댓글 작성은 금지합니다.
- 서버 요청은 `next.onFetch`, 브라우저 script/image 요청은 `page.route`로 제어합니다.
  기본 실행에서 `https://files.toosign.me`의 GET은 저장소의 `public/assets/images/profile.webp`로
  대체합니다. 브라우저와 서버에 같은 파일을 전달하며, 실제 서비스에 접속하지 않습니다.
  이 도메인을 대상으로 하는 브라우저의 `/_next/image` 요청도 고정 응답으로 대체해
  Next.js의 원격 이미지 DNS 조회와 다운로드를 실행하지 않습니다.
  실제 이미지 서비스 검사는 실행하지 않으며, 나머지 미등록 요청은 차단합니다.
  HTTP, 다른 포트·호스트, 유사한 도메인 및 해당 이미지 서비스의 쓰기 요청은 허용하지 않습니다.
- 이미지 메타데이터용 KV는 테스트 프로세스 메모리에서 GET·PUT을 대체합니다.
  제공된 이미지에서 생성한 메타데이터를 재사용하며 운영 Cloudflare에는 저장하지 않습니다.
- 링크 미리보기는 DNS와 TLS SNI에 의존하지 않는 공개 HTTP IP를 테스트 주소로 사용합니다.
  실제 외부 접속이나 TLS 인증서 검증을 대신하지 않습니다.
- 링크 미리보기는 HTML 512,000바이트 및 메타데이터 시작 태그 8,192자(UTF-16 코드 단위)
  제한 초과 시 413을 반환하는지, 반복된 미종료 태그에서도 정상 메타데이터를 처리하는지 확인합니다.
- Next testProxy는 `E2E_TEST=1`인 테스트 서버에서만 켭니다. 운영 환경에서는 켜지 않습니다.
- 조회수 테스트는 실제 Route Handler를 거치며 D1의 HTTP 응답만 대체합니다. 실제 DB SQL 실행·동시성 검증은 아닙니다.
- Giscus는 테스트 스크립트로 연동 계약을 검증하며 외부 서비스 자체의 가용성은 검증하지 않습니다.
  iframe의 `postMessage` 경계를 대체해 테마와 대상 origin을 확인합니다.
- 기본 실행은 로컬 이미지의 실제 최적화 경로를 검증하며, 원격 이미지는 고정 응답으로 대체합니다.
  자체 이미지 URL에 전달된 원본 bytes가 고정 파일과 일치하는지, 브라우저 표시와
  최적화 URL의 응답도 같은 고정 파일인지, 응답 200·이미지 형식·디코딩이 성공하는지 확인합니다.
  이미지가 있는 글을 다시 방문할 때 이미지 메타데이터 캐시가 재사용되는지도 확인합니다.
  미등록 이미지 호스트와 `files.toosign.me`로 시작하는 가짜 호스트도 차단되는지 확인합니다.
  실제 원격 이미지의 가용성·크기·화질과 운영 이미지 최적화는 이 E2E의 검증 범위가 아닙니다.
- 프로젝트 목록은 태그·정렬·검색어의 URL 동기화와 새로고침 후 복원, 잘못된 쿼리 정규화를 확인합니다.
- 검색·태그·정렬 조합의 결과와 URL을 확인하며, 상세 진입 후 브라우저 뒤로가기와
  검색어 수정 후 앞으로·뒤로가기에서 조건과 결과가 복원되는지 확인합니다.
  조건 변경은 현재 방문 기록을 대체하므로 입력마다 새 방문 기록이 생기는 것을 기대하지 않습니다.
- JavaScript 로딩을 보류한 상태에서 검색·정렬·태그 컨트롤이 비활성 상태인지 확인하고,
  준비 후 첫 검색어와 URL·결과가 일치하는지 확인합니다. 느린 로딩 중 입력 유실을 방지합니다.
- GitHub 기여 데이터가 빈 배열이거나 업스트림이 실패하면 기여 섹션이 렌더링 에러 없이 생략되는지 확인합니다.
- 모바일 메뉴는 390px 폭에서 열림·닫힘, 이동 후 자동 닫힘, 넓은 레이아웃 전환 시 닫힘을 확인합니다.
- sitemap의 모든 URL이 200 응답과 h1을 갖고 클라이언트 오류 없이 렌더링되는지 확인합니다.
- 글 상세 이동의 canonical 검사는 메타데이터 전환 중 이전·현재 태그가 잠시 겹치는 것을 기다리되,
  최종 URL의 canonical 태그가 정확히 하나만 남는지 확인합니다.
- 조회수는 D1 응답이 글 목록·상세 화면에 표시되는지, 상세 진입 시 방문 기록 요청이 전송되는지 확인합니다.
- 조회수 기록과 대체 조회가 모두 실패해도 본문 읽기와 목록·상세 이동을 계속할 수 있는지 확인합니다.
- 공유·연락처 복사는 클립보드 권한을 허용하고 `navigator.share`를 제거한 상태에서 복사 대체 경로를 확인합니다.
  운영체제 공유 시트 자체는 검증하지 않습니다.
- 클립보드 권한을 거부했을 때 공유 복사 오류를 표시하고 성공 알림을 표시하지 않는지 확인합니다.
- 모바일에서 목록·본문 읽기·링크 복사·목록 복귀 흐름을 확인합니다.
  목차는 현재 모바일에서 숨겨지는 설계이므로 모바일 목차 이동은 검증하지 않습니다.
- 조회수 기록 응답을 보류해도 글을 읽고 목록으로 이동할 수 있는지, 오류 후 같은 글에 재진입하면
  복구된 조회수를 표시하는지 확인합니다. 지연 검증은 임의 sleep 대신 응답 해제 신호를 사용합니다.
- 홈의 기여 달력 렌더링에 사용하는 브라우저 matchMedia API를 실패시켜 실제 오류 화면으로 진입하고,
  원인을 제거한 뒤 Retry와 Home으로 복구되는지 확인합니다. 운영 코드에 테스트 전용 분기를 넣지 않습니다.
- 댓글 스크립트 로드가 실패해도 본문과 공유를 계속 사용할 수 있는지 확인합니다.
  WebKit에서는 OS 클립보드 권한 부여·내용 읽기 대신 실제 legacy copy 명령의 성공 알림을 확인합니다.
- 모바일 긴 제목·코드 블록의 페이지 전체 가로 넘침, 메뉴 닫힘 시 버튼 포커스 유지,
  키보드 탐색·검색·태그 선택, 모바일 테마 변경 후 새로고침 복원을 확인합니다.
  정렬 select는 Tab으로 접근 가능한지 확인하며, OS 기본 선택창의 키보드 옵션 변경은 검증하지 않습니다.
  macOS WebKit의 링크·버튼 탐색은 기본 키보드 설정에 맞춰 Option+Tab을 사용합니다.
- WebKit 공유 대체 테스트는 Clipboard API를 제거하고 실제 legacy copy 명령의 성공 알림을 확인합니다.
  OS 클립보드 내용 읽기와 네이티브 공유 시트는 Chromium의 클립보드 검증과 별개입니다.
- robots.txt 내용과 페이지·피드·API 응답의 보안 헤더를 확인합니다.
- 개발 서버 검증이므로 프로덕션 빌드·CDN 캐시·배포 환경 검증을 대신하지 않습니다.

## 작성 기준

역할과 이름으로 요소를 찾고 상태가 나타날 때까지 assertion으로 기다립니다.
임의 sleep과 화면 전체 snapshot을 사용하지 않습니다.
성공·빈 결과·오류를 공개 응답으로 확인합니다. 프레임워크 전체를 mock하지 않습니다.
유닛 커버리지 수치와 E2E 성공 여부는 별도로 보고합니다.

## 실제 HTTP·HTTPS 콜백 회귀 검사

`tests/integration/*.test.mjs`는 Node 내장 테스트 실행기로 실제 로컬 TCP 서버와
`requestPinnedUrl`을 연결합니다. `pnpm test:integration`으로 실행하며 브라우저와 외부 접속은 필요하지 않습니다.
Node.js의 TypeScript 타입 제거 기능을 사용하며 CI의 Node.js 22 런타임에서 실행합니다.

정상 200 응답, 600 응답 변환 오류의 Promise 거절·소켓 종료, 요청 중단 후 다음 요청 성공,
무응답 요청의 시간 초과·소켓 종료를 확인합니다. HTTP 600은 중단 타이머 이전에 RangeError로
거절되어야 하며, 전역 예외 처리기로 오류를 숨기지 않습니다.

HTTPS 검사는 실행 시 OpenSSL로 하루 유효한 테스트 CA와 서버 인증서를 임시 폴더에 생성하고 종료 후
삭제합니다. `openssl` 실행 파일이 필요하며 시스템 인증서 저장소와 운영 키는 사용하지 않습니다.
테스트 파일의 격리된 Node 프로세스에서만 임시 CA를 신뢰하는 HTTPS agent를 사용하고 각 검사 후 복원합니다.
인증서 검증을 끄지 않고 다음을 확인합니다.

- 원래 호스트 이름과 TLS SNI를 유지하면서 지정한 로컬 IP에 연결해 200 본문을 받습니다.
- 신뢰하지 않는 CA 또는 인증서의 호스트 이름 불일치 시 HTTP 요청을 보내기 전에 거절합니다.
- TLS 연결 후 600 응답도 중단 타이머 이전에 RangeError로 거절하고 소켓을 종료합니다.

외부 운영 인증서의 만료·갱신 상태나 실제 인터넷 DNS·TLS 경로는 검증하지 않습니다.
