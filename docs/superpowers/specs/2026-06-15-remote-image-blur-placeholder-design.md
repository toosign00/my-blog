# Remote Image Blur Placeholder Design

## Goal

Replace the shimmer-only loading state for remote MDX body images with an
image-derived blur placeholder while preserving the existing aspect-ratio
handling and a shimmer fallback.

The change is limited to remote images rendered from post MDX. Existing
handling for local static imports, post and project covers, hero images, and
profile images remains unchanged.

## Current Behavior

Remote MDX images use `getImageSize()` to read `width` and `height` from
Cloudflare KV. On a cache miss, the application requests Cloudflare Image
Resizing metadata and writes the dimensions to KV.

`LazyImage` reserves the resulting aspect ratio, displays a shimmer layer, and
fades in the optimized Next.js image after its `onLoad` event.

Other image paths already use image-derived blur placeholders:

- Local MDX imports use the blur data generated by Next.js.
- Covers, hero images, and profile images use the existing Sharp-based
  `createBlur()` utility.

## Proposed Architecture

Replace the remote-image size lookup with a remote-image placeholder lookup.
The server utility will return:

```ts
type RemoteImagePlaceholder = {
  width: number;
  height: number;
  blurDataURL: string;
};
```

The lookup flow is:

1. Validate that the source uses HTTPS and belongs to `files.toosign.me`.
2. Read the versioned placeholder entry from Cloudflare KV.
3. Return a valid cached entry without fetching the source image.
4. On a cache miss or invalid legacy entry, download the source image once.
5. Use Sharp to read the original dimensions and generate a small WebP LQIP.
6. Store the dimensions and `blurDataURL` in KV.
7. Return the generated placeholder metadata.

The cache key will include a schema version:

```text
image-placeholder:v1:<source-url>
```

Changing the LQIP format or generation settings will require incrementing the
version. Existing dimension-only entries can remain in KV and will no longer be
read.

## LQIP Generation

The existing direct Sharp approach will be retained. Plaiceholder will not be
added because it also uses Sharp internally, has no persistent cache, and is in
maintenance mode.

The remote placeholder will use these initial settings:

- Fit within 10 by 10 pixels while preserving aspect ratio.
- Apply a small Sharp blur.
- Encode as WebP at low quality.
- Return the result as a Base64 data URL.

The original image buffer must be reused for both metadata extraction and LQIP
generation so each cache miss downloads the source only once.

## Rendering

The MDX image renderer will pass the returned values to `LazyImage`:

```tsx
<LazyImage
  src={src}
  width={placeholder?.width}
  height={placeholder?.height}
  blurDataURL={placeholder?.blurDataURL}
/>
```

When `blurDataURL` is present, `LazyImage` will render Next.js `Image` with:

```tsx
placeholder='blur'
blurDataURL={blurDataURL}
```

Next.js will replace the placeholder when the optimized image finishes loading.
For the blur path, the image will remain visible so the Next.js placeholder is
not hidden by the current `opacity-0` class. The shimmer layer and client load
state will only be active when `blurDataURL` is absent.

When placeholder metadata is unavailable, `LazyImage` will retain the existing
behavior:

- Use the default 1200 by 800 aspect ratio when dimensions are unavailable.
- Display the shimmer layer.
- Fade in the image after `onLoad`.

This fallback prevents metadata or source-image failures from breaking post
rendering.

## Error Handling

Remote placeholder generation is optional presentation work. Failures must not
fail the page or production build.

The utility will return `null` for:

- Unsupported protocols or hosts.
- Source-image fetch failures.
- Invalid image metadata.
- Sharp processing failures.

KV read failure will be treated as a cache miss so placeholder generation can
still proceed. KV write failure will not discard a newly generated placeholder;
it can still be returned for the current render even when it cannot be
persisted.

HTTP responses and image buffers must not be logged. Error logging, if retained,
must exclude credentials and Base64 payloads.

## Security

Only `https://files.toosign.me` may be fetched by the placeholder utility. This
matches the configured remote image source and prevents arbitrary server-side
URL fetching.

Cloudflare credentials remain server-only and must not be passed into
`LazyImage` or other client components.

## Testing

Focused tests should verify:

- A valid KV entry is returned without downloading the source image.
- A cache miss downloads the image once and stores dimensions plus
  `blurDataURL`.
- A legacy dimensions-only KV value is treated as a cache miss.
- KV write failure still returns the generated placeholder.
- Invalid hosts and source-image failures return `null`.
- `LazyImage` uses blur props when `blurDataURL` exists.
- `LazyImage` retains shimmer behavior when placeholder data is absent.

Project verification will run the repository type check and lint checks. A
production build should also be run when the required Cloudflare environment
variables are available.

## Non-Goals

- Replacing the existing blur handling for local images, covers, or profiles.
- Adding Plaiceholder or BlurHash.
- Removing Cloudflare KV.
- Adding a background regeneration service.
- Migrating existing dimension-only KV entries.
